# FDE 售前沟通方法论 V3.0（基于真实客户现场实录深度提炼）

> 来源：真实政务/财政/审计/经发办 88 分钟现场调研实录深度复盘。
> 定位：面向 AI 解决方案 FDE（Forward Deployed Engineer / 驻场售前专家），以“先看现场、死咬痛点、精准四维归因、工程化降维翻译、坦诚划界小步验证”为核心。

---

## 一、十大底层沟通原则（V3.0 完整版）

1. **先看现场，不聊文档（眼见为实）**
   - 当客户反馈“方案/技术文档太专业看不懂”时，立刻跳过文档，直接要求看实际工作界面、截图、业务表单或真实原始文档。
2. **拒绝方案先行，死咬业务痛点**
   - 客户一旦开始提具体形态（“做个小程序 / 接个 API / 上 DeepSeek+RAG / 买几张显卡”），立即礼貌但坚定地打断：“先不说解决方案，先说现在最卡壳的业务问题是什么？”
3. **场景还原四要素 + 输入输出对齐**
   - 绝不接受空泛形容（“不好用/很乱/不准/太慢”），必须追问到底：**什么文件格式（Word/Excel/PDF/图片）→ 单文件还是打包多文件 → 现在怎么操作 → 期望产出什么结论 → 实际错在哪一步**。
4. **精准四维归因（不拿 AI 杀鸡）**
   - 区分问题的真实本质，避免把所有问题都甩给大模型：
     - **人的问题**：线下操作不登记、口径随手填（如挪桌子不改台账）；
     - **流程制度问题**：跨部门审批口径不统一、二次审核链路冗长；
     - **常规工程/数据结构问题**：未变化数据重复推送（实为数据库快照 Diff 逻辑）、容器存储上限、函数 60 秒超时；
     - **AI 架构错配问题**：用单次对话 Prompt 干复杂多轮业务（缺 Agent 引擎与 Skill）、用多模态大模型干 OCR 导致超时、用大模型做简单分类（应换小决策模型）、用过时切片 RAG 做知识库（应升级向量检索或 LLM-Wiki）。
5. **业务问题先行，平台能力反哺（FDE 思维 vs 平台思维）**
   - 平台方倾向于先抽象通用能力，FDE 坚持先用最贴合场景的轻量技术打通业务闭环，跑通后再沉淀为平台公共能力（OCR API、对象存储 Bucket、语音转文本 API、轻量 Agent 引擎）。
6. **七项硬边界前置排查**
   - 痛点清晰后、给方案前必须摸清七项现实约束：
     1. **存储与容量**：数据与过程文件（如万级实物照片）存哪？过程数据扔不扔？容器有无 100MB 限制？
     2. **网络与跨端**：纯内网隔离还是政务外网？外勤手机端能否访问内网应用？
     3. **数据规模与变动频次**：存量多大？月均变动多少条？
     4. **终端与运行时限制**：PC 浏览器还是手机？注意 H5 网页录音息屏会断、云端函数超时等运行时红线！
     5. **保密合规与权限**：涉密不出域要求、私有数据 vs 上级规则共享权限边界。
     6. **历史数据与样例沉淀**：有无过往案例/脱敏文档？即使“一案一例”也可通过向量化语义检索复用。
     7. **既有系统与接口约束**：老系统是否有 API、是否需要密钥登录、现有工具格式能否修改。
7. **复述闭环与剥离已解决项**
   - 遇到表述矛盾（如纯内网 + 手机外勤随时查）或业务绕圈时，快速复述对齐；同时帮客户剥离“已经解决的环节”，直指剩余真卡点。
8. **坦诚划界：确定结论、专项验证、礼貌后置**
   - 做过的成熟方案给确定结论；触及深水区（如万级台账语义口径清洗 / Ontology 本体论）坦诚说明未做过需专项验证并排后；不确定性宏大需求（如宽泛“产业图谱”）礼貌拒接并引导落回单一真实场景。
9. **技术概念降维翻译 + 赋能客户提需求**
   - 用生活比喻消除技术隔阂，并教客户下次怎么用一句话给 AI 提需求（“不是训练大模型，而是打磨自己的 Skill”）：
     - **大模型 = 汽油（92/95/98 号）**，直接点燃只能简单发热（对话式）；
     - **Agent 引擎 = 发动机**，让模型循环多轮做功；
     - **Skill / MCP = 轮子、车把与改装件**，装上才能按业务规则稳定干活；
     - **多轮验证 = 避免注意力分散（Attention）**，几十条合同审核规则必须拆轮次专注核对；
     - **轻量专用模型 = 不拿牛刀杀鸡**，简单分类用小决策模型，文字识别用纯 CPU 200ms/页 OCR 而非慢速多模态。
10. **不推倒重来，脱敏样例小步快跑**
    - 充分肯定客户已有的业务逻辑，不要求推倒重做，而是“保留业务逻辑 + 嵌入轻量 Agent 引擎 + 用 10–20 份脱敏样例先跑通最小闭环”，按 S0→S5 严格有序推进。

## 二、十二大实战 Skill 规则库

| # | Skill ID | 名称 | 允许阶段 | 触发条件 | 提词器短问句示例（≤24字） |
|---|---|---|---|---|---|
| 1 | `interrupt_solution_first` | 打断方案先行 | S1 | 客户提 App/小程序/API/大模型/显卡等方案 | “先不说方案，现在最卡壳的业务问题是什么？” |
| 2 | `scene_restoration_probe` | 场景还原追问 | S0, S1 | 回答空泛、看不懂文档或描述不清输入输出 | “能直接看界面或举例：传什么文件、卡在哪？” |
| 3 | `vague_demand_redirect` | 模糊需求拒接引导 | S1 | 提出宏大抽象目标（企业大脑/产业图谱/全面智能） | “方向太大，先切一个最具体高频的单点场景？” |
| 4 | `root_cause_distinction` | 四维根因深挖 | S2 | 归咎系统或 AI 不准但原因混杂 | “这是人没录、流程卡住，还是系统或AI没拆步骤？” |
| 5 | `ai_vs_engineering_triage` | AI 与常规工程分诊 | S2, S5 | 用 AI 干纯程序比对/用多模态干 OCR/大模型干简单分类 | “这更像程序比对或专用OCR，真要上大模型吗？” |
| 6 | `paraphrase_loop_confirm` | 复述闭环确认 | S2, S4 | 前后矛盾、业务绕圈或需剥离已解决环节 | “我复述确认下：前面已解决，真卡点在这对吗？” |
| 7 | `boundary_constraints_confirm` | 七项边界约束确认 | S3 | 痛点根因已清，但缺存储/网络/量级/终端/保密/样例/接口 | “核对下边界：数据存哪、纯内网吗、过程图留不留？” |
| 8 | `pain_point_convergence` | 痛点验证收口 | S4 | 收集多个痛点需收敛排优先级 | “这几个痛点里，一期先打透哪一个见效最快？” |
| 9 | `honest_boundary_defer` | 坦诚划界与验证后置 | S1, S4, S5 | 遇到深水区（本体清洗）或不确定性跨行业需求 | “这块复杂度高需先验证，先排到二期行吗？” |
| 10 | `tech_concept_translation` | 技术概念降维翻译 | S5 | 解释 Agent/Skill/向量化/OCR/注意力分散等概念 | “打个比方：模型是汽油，Agent是发动机，Skill是改装件。” |
| 11 | `prototype_and_sample_anchor` | 脱敏样例与存量改造锚定 | S3, S5 | 担心推倒重来、缺训练样本或不知如何启动一期 | “不用推倒重来，能先给几份脱敏样例试跑吗？” |
| 12 | `stage_progression_control` | 阶段推进控制 | S5 | 痛点与边界已对齐，推进方案与下一步行动 | “痛点和边界都齐了，接下来聊一期落地思路？” |
